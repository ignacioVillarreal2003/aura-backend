Plan #2 — Contextual Retrieval (situar cada chunk antes de embeber)

Objetivo

Que el vector de cada fragmento incorpore contexto del documento (descripción/sección/resumen) para no perder el "de qué
trata esto" al recuperar chunks aislados. Estilo
Anthropic Contextual Retrieval, pero reaprovechando lo que ya generás.

Problema de secuencia (clave de este plan)

Hoy el orden es: ingesta → embed → persist → (async) enrichment. La description del documento y los summary de fragmento
no existen todavía cuando se embebe. Además, el texto
contextualizado de Docling (embed_text) es efímero: no se persiste y reembed_document_service re-embebe usando
fragment.content crudo (se pierde hasta el contexto de headings al
cambiar de modelo).

Por eso este plan tiene dos sub-decisiones:

A) ¿Cuándo se contextualiza? → Recomiendo hacerlo como paso final del enrichment (cuando description + summaries ya
existen), vía un re-embed contextual. Reutiliza la infra de
reembed.

B) ¿Cómo se arma el prefijo? Dos variantes:

- B1 (recomendada, barata, sin LLM extra): prefijo determinístico concatenando lo ya generado:
  "{doc.name} — {doc.description}\n[Sección: {section_path}]\n{fragment.summary}\n\n{content}".
- B2 (Anthropic puro, cara): una llamada LLM por chunk que redacta 1–2 frases situando el chunk dentro del documento
  completo. ~1 call/fragmento → coste alto. Se puede dejar como
  opción configurable a futuro.

Archivos a tocar (aura-document-processing-service)

1. Migración + ORM app/infrastructure/persistence/database/orm/fragment.py: nueva columna embed_text: Text | nullable (
   texto efectivamente embebido) y/o context_prefix. Esto fija
   el problema de efimeridad y permite re-embeds idempotentes. → requiere script de migración (ver dónde viven las
   migraciones; hay que confirmar Alembic).
2. Ingesta app/application/services/document/document_ingestion_service/document_ingestion_service.py: persistir el
   embed_text que ya se usa en texts = [chunk.embed_text or
   chunk.text ...] (hoy se descarta).
3. Nuevo processor app/application/services/document/.../contextual_reembed (o extender reembed_document_service.py):
   arma el prefijo contextual B1 y re-embebe. Necesita
   EmbedderFactory (ya disponible) + acceso a document.description.
4. Enrichment app/application/services/document/document_enrichment_service/document_enrichment_service.py: agregar 3er
   paso "contextual re-embed" tras metadata+fragments.
   Inyectar el nuevo processor (tocar app/configuration/dependencies.py).
   - Alternativa más desacoplada: publicar un evento nuevo contextual_embed al final del enrichment y consumirlo (tocar
   publishers/consumers). Más piezas, pero no bloquea el
   enrichment.
5. reembed_document_service.py: cambiar _embed_contents para que use embed_text (con fallback a content) en vez de
   content crudo, así los cambios de modelo preservan el contexto.
6. (Opcional, BM25) Para que la búsqueda léxica también se beneficie, el índice ParadeDB content @@@ debería apuntar al
   texto contextualizado. Eso implica decidir si BM25 indexa
   embed_text o una columna nueva. Lo marco como fase 2 porque cambia el índice de búsqueda y el comportamiento de
   relevancia.
7. Tests: test/test_document_ingestion_service.py (persistencia de embed_text), test/test_document_reembed_controller.py
   y nuevos tests del processor contextual.

Riesgos / decisiones

- Migración de datos: documentos ya ingeridos no tienen embed_text ni contexto. Hay que decidir backfill (re-embed
  masivo) o aplicar solo a documentos nuevos. El re-embed masivo
  tiene coste de cómputo.
- Coste: B1 es casi gratis (sin LLM nuevo, solo re-embeddings). B2 es caro.
- Citas y display: content se mantiene crudo para mostrar/citar; solo el vector cambia. Importante no contaminar lo que
  se muestra al usuario.
- Truncación por token window: el prefijo agranda el texto a embeber → vigilar huggingface_max_seq_length (el embedder
  ya avisa de truncación). Hay que recortar el prefijo para
  no empujar el contenido real fuera de la ventana.
- Confirmar herramienta de migraciones (Alembic u otra) antes de proceder — es el punto que más necesito validar.

Esfuerzo

Alto (cambio de esquema + pipeline + migración/backfill). Mayor ganancia de calidad de los tres.
